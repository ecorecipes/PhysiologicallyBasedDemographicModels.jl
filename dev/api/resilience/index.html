Resilience

Resilience metrics for PBDMs come from ResilienceCore.jl (operators and their metrics) and DynamicalResilience.jl (continuation, fixed points of maps, and simulation-based recovery). This package supplies:

  • an integrator for PBDMProblem (init, step!, reinit!, set_u!, …), so that DynamicalResilience's recovery runs on a PBDM unchanged;
  • the state of a population, system or problem as one vector;
  • the annual map of a model under a repeated weather year, its fixed point (the annual cycle) and the cycle's Floquet multipliers;
  • linearise for the consumer–resource equilibria of the theory helpers, and the same model as an ODEProblem for continuation along temperature.

See the tutorial Resilience of PBDMs (vignette 65).

Integrator

PhysiologicallyBasedDemographicModels.PBDMIntegrator — Type
PBDMIntegrator

The integrator returned by init(prob::PBDMProblem, DirectIteration()). It steps a copy of the problem's populations one day at a time, exactly as solve does, and implements the part of SciML's integrator interface that DynamicalResilience.jl uses:

  • integ.t: the last completed calendar day (first(prob.tspan) - 1 before the first step);
  • integ.u: full_state of the populations after day integ.t;
  • step!(integ) advances one day; step!(integ, dt, true) advances dt days (dt must be a whole number of days);
  • reinit!(integ[, u0]) restarts from the problem's populations (or from the state u0) at first(prob.tspan) - 1. PBDMs are deterministic and weather is a function of the day, so a run replays exactly;
  • set_u!(integ, u) writes a new state; or change integ.u in place and then call derivative_discontinuity!(integ, true);
  • terminate!(integ) stops further steps; check_error(integ) returns ReturnCode.Failure once a state entry is not finite, ReturnCode.Terminated after terminate!, and ReturnCode.Success otherwise;
  • integ.p (the problem's parameters) may be reassigned between steps.

Covered: single-species problems (SingleSpeciesPBDM, density-independent or density-dependent, deterministic; give a density-dependent problem's reproduction_fn to init, as to solve) and coupled PopulationSystem problems (MultiTypePBDM, MultiSpeciesPBDMNew, …). Each day runs PREEVENT callbacks, events, state variables, stress, stepping, rules and ENDOF_DAY callbacks; observables are not recorded. Events and rules must not keep their own mutable state between days, or a replay will not be exact.

solve(prob) steps prob.populations in place, so init a problem before solving it, or remake it, if the integrator should start from the original state.

CommonSolve.init — Method
init(prob::PBDMProblem, alg = DirectIteration(); reproduction_fn = nothing, seed = nothing) -> PBDMIntegrator

An integrator over the days of prob, starting from a copy of prob.populations (see PBDMIntegrator). seed is accepted for compatibility with stochastic SciML problems and ignored: the problem types covered are deterministic.

State vectors

PhysiologicallyBasedDemographicModels.full_state — Function
full_state(x) -> Vector{Float64}

The numerical state of x as one vector:

  • a Population: the contents of every substage of every stage's distributed delay, stage by stage;
  • a BulkPopulation: its value;
  • a PopulationSystem: its components in keys(sys) order, then its ScalarState and ArrayState variables in order of name;
  • a PBDMProblem: its populations.

Other state variables (DictState, GenomeState, DiapauseState, …) belong to the system and are copied and restored with it, but are not part of the vector: they are neither perturbed nor linearised. set_full_state! is the inverse and full_state_labels names the entries.

PhysiologicallyBasedDemographicModels.set_full_state! — Function
set_full_state!(x, u) -> x

Write the state vector u, laid out as by full_state, into the population, system or problem x. Values are stored as given: a negative entry is not clipped (perturbations used to linearise a map can be negative), but a BulkPopulation above its carrying capacity is.

PhysiologicallyBasedDemographicModels.full_state_labels — Function
full_state_labels(x) -> Vector{String}

Names for the entries of full_state(x): "pest.larva[3]" for the third substage of stage larva of component (or population) pest, "scale" for a BulkPopulation, "state.temperature" or "state.pools[2]" for state variables.

Annual cycles

PhysiologicallyBasedDemographicModels.annual_map — Function
annual_map(prob; period = 365, t0 = first(prob.tspan), reproduction_fn = nothing) -> F

The map F(u) that takes a state u (laid out as by full_state) at the start of day t0 to the state period days later, by stepping prob's model through days t0, …, t0 + period - 1 with init/step!. Every evaluation reuses the same weather days, so F is the year-to-year map under that weather year repeated: with weather that is periodic in the day (SinusoidalWeather, or a WeatherSeries built from a periodic function) its fixed point is the model's annual cycle. Scheduled events fire on their calendar days in every evaluation, so a one-off event (a single release) becomes an annual one.

PhysiologicallyBasedDemographicModels.annual_fixed_point — Function
annual_fixed_point(prob; period = 365, u0 = full_state(prob), spinup = 0,
                   method = :finite_differences, h = 1e-6, tol = 1e-9, maxiters = 50,
                   reproduction_fn = nothing)
    -> (u, multipliers, jacobian, converged, iterations)

The annual cycle of prob under its repeated weather year: a fixed point of annual_map, found by DynamicalResilience's fixed_point (Newton's method) after spinup plain iterations of the map from u0. jacobian is the DiscreteJacobian of the annual map there and multipliers its eigenvalues, the cycle's Floquet multipliers: the cycle is stable when every multiplier has modulus below one, and the leading modulus is the factor by which a small perturbation shrinks per year.

The Jacobian is taken by finite differences, since PBDM's populations store Float64 and do not carry dual numbers. Each column uses a central difference with step h · max(|u_j|, 1), except where that step would make the entry negative: there it uses a forward difference. Populations cannot be negative and PBDM code clips them at zero, so at a cycle on which a species is absent the map has a kink, and a central difference would average the true growth of a rare invader with the clipped side (halving it, for instance). The forward difference gives the multiplier of the absent species correctly: its growth factor per year when rare, so the cycle resists invasion when it is below one.

Newton converges to the cycle near its starting point whether it is stable or not; a model that runs away (unbounded growth) has no cycle to find.

ResilienceCore.linearise — Method
linearise(prob::PBDMProblem; period = 365, check = true, kwargs...) -> DiscreteJacobian

The DiscreteJacobian of the annual map of prob at its annual cycle, from annual_fixed_point (kwargs are passed to it). ResilienceCore's metrics then apply per year: resilience is −log ρ, with ρ the leading Floquet multiplier's modulus. With check = true an error is thrown if Newton's method did not converge.

Consumer–resource theory

ResilienceCore.linearise — Method
linearise(r::EquilibriumResult) -> ContinuousJacobian

The Jacobian of the consumer–resource model at the interior equilibrium found by find_equilibrium, with the equilibrium (M₁*, M₂*), as ResilienceCore's ContinuousJacobian. Its eigenvalues are r.eigenvalues. Throws if there is no interior equilibrium (the consumer cannot persist).

PhysiologicallyBasedDemographicModels.consumer_resource_problem — Function
consumer_resource_problem(fr::FraserGilbertResponse, resp::Q10Respiration, T;
                          intrinsic_rate, carrying_capacity, consumer_demand_rate,
                          conversion_efficiency = 1.0, u0 = nothing, tspan = (0.0, 100.0))
    -> ODEProblem

The resource–consumer model behind find_equilibrium as a SciML ODEProblem:

dM₁/dt = r M₁ (1 − M₁/K) − d₂ M₂ (1 − exp(−a M₁/(d₂ M₂)))
dM₂/dt = (ε d₂ (1 − exp(−a M₁/(d₂ M₂))) − R₂(T)) M₂

with R₂(T) the consumer's Q10Respiration at temperature T. The parameters p are a NamedTuple with fields a, r, K, d2, eps, resp, T, so DynamicalResilience's resilience_along(prob, (p, T) -> merge(p, (T = T,)), temperatures) follows the equilibrium along temperature. u0 defaults to the equilibrium from find_equilibrium when it exists.
